- UI chrome (2026-10-23): the kernel is soft-float, so wm.c motion uses integer cubic-bezier LUTs and the resize cursors are baked bitmaps (a float AA-line cursor failed to link with `__mulsf3`). The panic card and splash draw only with fb.c and theme 0, never the heap. `/etc/apps` gained a description column; the shell title OSC is now `user@host: path` and termwin appends " — Terminal". Windows place right of the desktop icon column when they fit. Idle compositor CPU 0.2% in `top`.

Gotchas: the Trash folder doesn't exist until something is trashed, so the sidebar used to toast "No such folder" (Files now creates it); a `files` binary rebuild re-images the disk, so drag-and-drop tests must create their files in the same VM run. Stripped sizes: files 392→658 KB (the 24/32/48 px file-icon tables, all linked by `fileicon_get`), viewer 272→301 KB, music 428→440 KB.
- Editors + Browser port (2026-10-23): the browser alert was drawn by hand with a 90-alpha black wash over the page only and a `surface` fill, so in light it read as a dark page-modal box; it now goes through the toolkit dialog (window-wide `scrim`, `overlay`, E4). `ui_tabbar` has no close boxes, so Code pads each tab name with trailing spaces to reserve 28px and draws the close box over that space (the close press is taken before the tab strip sees it). Internal browser pages carry a fixed-length `<body bgcolor text link>` tag that a theme change rewrites in place, then relayouts. The JS alert button says "Close", not "OK" (DESIGN §9).
- Games (2026-10-23): content colours come from `ui_th.term.pal`, so a theme switch (or `contrast`) recolours Tetris pieces, Snake and Minesweeper numbers with no per-game palette; light themes soften fills by mixing toward the window. Doom's no-WAD window draws with plain gfx: any `ui_*` call pulls ui_end's overlay code and with it the Lucide masks (~120 KB) into doom.

Paint at 960x680 did not fit a 1024x768 screen under the 40px panel (its title bar sat off-screen), so it opens at 880x652.
