### Kernel, filesystem, libc (perf-kernel)
Method: `/bin/sysbench` (`sysbench -k [-w] [sys spawn pingpong pipe fsmall f4m dir fault str malloc stdio kmsg]`; `--autostart 'term /bin/sysbench -k'` then `wait:BENCH-DONE`; `-w` times make/tcc/python/qjs/lua/sh) with rdtsc spans, same machine and QEMU/KVM before and after (the host is shared, so single runs wobble +-20%: best-of-7 for ping-pong, otherwise the median of several runs). `/proc/diskstats` counts ATA commands. Checks: `/bin/fasttest` (in `runtests.sh`: 11 MB files past the cache size, partial-block overwrites, holes/truncate, exec of a just-written file, 300 small files, pipe wrap, x87 state across threads/children/signals, malloc, thread lock), `tools/ext2test` (now also with a 256 KiB cache that forces eviction), `tools/libctest` (string fast paths for libc and the kernel's string.c, every size and alignment); `e2fsck -fn` clean after `suites`; suites also green under `VIBE_ACCEL=tcg`.
- [x] Disk was the whole story: ext2 did one 1 KiB ATA command per block, each costing ~150-250 us of VM exits and QEMU latency (cold read 4 MB/s, 4 MB write 0.9 MB/s, `unlink` of 4 MB 1.07 s, `python -c pass` 127 ms). Now: hashed LRU block cache of up to 8 MiB (was a 1 MiB linear scan), read-ahead of up to 64 KiB of physically contiguous blocks per command, dirty blocks sorted and written as runs, and write-back delayed until the CPU idles, 256 blocks are dirty or 1 s has passed (`fsync` is now a real syscall, `SYS_fsync` 92; shutdown/reboot flush; writing to `/dev/kmsg` flushes first because tests report through it and the harness may quit the VM the instant it sees the line, which `e2fsck` caught once). New files start at an allocation frontier so they come out contiguous; bitmap scans skip full bytes. ATA: one status read instead of four for the 400 ns delay, drive select skipped when unchanged, one IRQ status read: ~35% off every command.
- [x] Before -> after: cold read 4 MB 3.9 -> 278 MB/s; warm read 4.9 MB/s -> 5 GB/s; write 4 MB 0.9 -> 153 MB/s (4 KiB chunks); `unlink` 4 MB 1067 ms -> 0.5 ms; create+write+close 1 KiB 3541 -> 46 us; unlink 1 KiB 2038 -> 2 us; `stat` in a 1000-file dir 42 -> 5 us; readdir of it 1756 -> 251 us; stdio `fputs` to a file 0.55 -> 139 MB/s, `fgets` 2.4 -> 198 MB/s. Cold first runs: python -c pass 127 -> 7 ms, qjs -e 0 190 -> 12, lua -e '' 114 -> 5, tcc hello.c 152 -> 62, make wordfreq 165 -> 30, shtest.sh 157 -> 101; spawn+wait /bin/true 226 -> 18 us; in-VM suite time (proctest..qjs, sequential) 15.3 -> 6.3 s (maketest's two `sleep 1.05` are 2.1 s of what is left).
- [x] Switching: FPU state is lazy (`CR0.TS` + `#NM`; `fpu_ensure` for signals/exec), the kernel identity map is global (`CR4.PGE`), `isr_common` no longer reloads ds/es/fs/gs on entry (the user data segment is flat): null syscall 200 -> 145 ns, pipe ping-pong round trip 1850 -> 1170 ns (fnsave+frstor were 456 of ~780 cycles per switch). Pipes copy with `memcpy` up to the wrap point: 326 MB/s -> 5.5 GB/s.
- [x] libc/kernel string functions: short `memcpy`/`memset` are overlapping word moves (8 B 8 -> 3 ns, `memset` 24 B 15 -> 2 ns), `strlen` and `memcmp` go a word at a time (strlen 64 KiB 3.4 -> 7.3 GB/s), backward `memmove` by words (3.6 -> 7.1 GB/s); `rep movsb` kept from 32 B up (rep movsl was slower at 100 B). malloc: freed blocks up to 128 B wait on per-size stacks and merge back when the heap would grow, and a bitmap finds the next non-empty bin: malloc+free 24 B 454 -> 9 ns, mixed 429 -> 23 ns. After the last `pthread_join` libc's lock switches off again (`gettid` per malloc/fgetc otherwise; fgets fell to 5.8 MB/s after any thread).
- Tried / left alone: batching serial output (QEMU's 16550 takes ~17 us per byte whatever the burst, so a `[proc]` line costs 0.6 ms of guest time; only an interrupt-driven TX ring would hide it, not worth it for a 700-byte boot log); `fxsave` instead of lazy FPU (ABI churn, lazy wins more); bss and ELF segments are still mapped eagerly (<= 1 MB bss: 30 us); 100 Hz timer (idle VM is already 1.6% of a core); dentry cache for huge directories (create in a 1000-file dir is 50-150 us).
- Remaining hotspots: each ATA command is ~150 us (QEMU latency, not guest work), so scattered metadata flushes cost that per block; the kernel `[proc]` log lines (serial pacing); page faults on never-touched frames (~0.8 us, host EPT); a context switch is ~585 ns of which ~200 are the CR3 reload and ~130 the run-queue scan.
- Durability change to know about: ext2 writes are no longer on disk when `write()` returns, but within ~1 ms of the CPU going idle (or at once on `fsync`, shutdown, a `/dev/kmsg` write, or 256 dirty blocks/1 s). A panic or a `quit` while the guest is busy loses the unflushed tail; an image that was idle (or reported through kmsg) is fsck-clean.
- Shared files touched: `common/abi.h` (+`SYS_fsync`), `Makefile` (one `-fno-tree-loop-distribute-patterns` line for kernel/lib/string.c), `root/home/runtests.sh` (+`r fasttest`), `tools/libctest/*`, `tools/ext2test/*`, `docs/ARCHITECTURE.md`; the apps agent's `bench` stays, mine is `sysbench`.

### Kernel, memory, compositor, command line, apps (perf-usability)

- [x] Syscalls: 0-3 argument calls use `sysenter`/`sysexit` (libc `__syscall0..3`; return eip in EBP, esp in ESI, ECX/EDX

- [x] `poll()`: a sleeper whose files are all pipes, terminals, sockets or windows (`poll_keyed_ops`) wakes only when one of

- [x] ext2: a 2048-entry name -> inode cache (positive only, invalidated on add/remove/setino and cleared when an unlinked inode
